Upande Quality — Developer Guide

A React Native (Expo Router) field-operations app for Frappe/ERPNext flower-quality and post-harvest workflows. One binary serves several Frappe instances; the active tenant is resolved from the logged-in instance URL. Karen is the complete feature set; the other tenants are traceability-only over the same core.

This guide covers the architecture, the operator workflows screen-by-screen, an interactive API explorer for every backend method the app calls, and a reference of the Frappe DocTypes involved. The backend methods are Frappe whitelisted functions (Server Scripts or app methods) reached at /api/method/<name>.

How to read this
The API explorer is the source of truth for request/response shapes — expand any endpoint for its parameters, body, response, error behaviour, and the DocTypes it touches. The workflow sections explain when each call fires.

Multi-tenant model

Tenants are an enum in src/core/tenant/instance-mapper.ts: KarenKikwetuXfloraMonaTambuziDemo. There is no tenant picker — URL_TO_TENANT maps each concrete instance URL (prod, staging, LAN IPs) to a tenant, and getTenantByUrl(url) resolves it after login. Demo reuses Karen's feature set.

Per-tenant wiring is done with resolvers in src/composition/: getDrawerFor(tenant) (navigation menu), getTraceabilityRepository(tenant) (all 5 implement it), and getReplacementRepository(tenant) (a Partial map — only Karen/Demo present; others render a "not available" placeholder). Karen's drawer exposes ~15 screens; Kikwetu/Mona/Xflora expose only Traceability + Receiving; Tambuzi is empty.

Networking

  • Base URL is resolved per request: the axios request interceptor reads StorageKeys.instanceUrl from AsyncStorage on every call (src/core/api/client.ts), so the active instance can change without rebuilding the client.
  • Auth is cookie-based — the interceptor forwards the stored Frappe Cookie (carrying sid=) verbatim. No Authorization/token header in the app.
  • Defaults: Content-Type: application/json (unless set), timeout: 30000ms.
  • api<T>(config) is the canonical helper — runs the request and returns res.data (the whole Frappe envelope) typed as T; unwrapping message/data is the repository's job.
  • Errors: HttpError{status, body}; mapAxiosError() turns a no-response failure into HttpError(0, "You're offline…") and otherwise prefers the Frappe message field.
  • Uploads bypass axios: uploadImage() uses raw fetch + FormData to POST /api/method/upload_file (the JSON content-type interceptor would break the multipart boundary).
  • Cleartext / local HTTP: LAN instances are plain http://. Enabled via expo-build-properties → android.usesCleartextTraffic: true and iOS NSAppTransportSecurity.NSAllowsLocalNetworking: true in app.json.

Auth & login

  • URL probe — probeBaseUrl() trusts a typed scheme, else tries https:// then falls back to http:// (5s HEAD probe).
  • Login — POST /api/method/login with form-encoded usr+pwd (classic Frappe session login). On 200 the sid= cookie is extracted and persisted alongside instanceUrl, backups, and fullName.
  • Roles — getCurrentUserRoles is fetched after login and cached; hasRole() treats Administrator as having every role. Role failure is non-fatal.
  • Biometric — if enabled and a password_backup exists, the OS prompt re-runs the password login silently. logout() is soft (keeps cookie + biometric); forgetDevice() wipes everything.

Connectivity / offline

The network store (src/core/network/store.ts) blends OS connectivity (expo-network) with API-failure escalation: after FAILURE_THRESHOLD = 2 consecutive no-response failures it flips to offline even if the radio is up — the practical signal is "is our server reachable." Polls every 15s online / 6s offline; a sticky OfflineBanner shows at the root. The app is online-first (no offline write queue).

Scanning

Scanning is the primary input. ScanField is a TextInput tuned for Honeywell-style HID scanners: since workflows scan JSON QR payloads, it treats valid JSON ending in } as the scan-complete signal (no Enter needed), debounces 300ms, plays a beep, clears, and refocuses. focusWhenReady() defers focus past Android nav transitions so operators never tap. A camera fallback (/camera-scanner, expo-camera) returns a single result via a module-level callback bridge.

Navigation

Two layers via expo-router. The root Stack (headers off) holds (tabs), login, biometric-lock, and the two camera screens as full-screen modals; an auth-gate effect routes by session/biometric state. The bottom tabs are icon-only with crossfading outline/filled icons; visible tabs are Home, Traceability, Replacement, Receiving, Shelving, Intake QC, Discards. Everything else (href:null) is reachable only from the drawer (SideMenu, driven by the per-tenant drawer map).

Conventions

  • Response envelope — whitelisted methods wrap results in message; REST resource endpoints use data. The code reads res.data ?? res.message defensively. Several methods nest deeper (message.data, message.status) or under data — each repository normalizes its own shape (noted per endpoint below).
  • Error shapes — Frappe bodies carry { exc_type, _server_messages, message } and often a custom http_status_code + error/status. Most custom POSTs use validateStatus:()=>true so 4xx/5xx bodies are read as payloads rather than thrown; only getTraceability throws on HTTP error.
  • Request style — almost everything is POST /api/method/<fn> with a JSON body; login is the one form-encoded exception; picker data uses frappe.client.get_list or /api/resource/<Doctype>.

Workflow · Logistics

The cold-chain path from a remote farm to the packing line. Screens: Receiving → Shelving → Bucket Requests (trolley transfer) and the shared Pending Reshelving inbox.

Receiving — /receiving

  • Optional Batch mode generates an 8-char id that groups consecutive scans.
  • Scan a bucket QR → createReceivingStockEntry with the current batch id.
  • received → success popup (variety, stems, bunches, greenhouse, harvested date) that auto-dismisses after 1.7s and refocuses; already_received/no_harvest_on_date → inline card; not_harvested/not_exist/error → danger alert.

Shelving — /shelving

  • Scan a shelf QR (sticky/active), then scan bucket QRs onto it → createShelvingEntry({farm, shelf_id, bucket_id}).
  • success → "Shelved" card; failed → diagnostic card with a typed reason (e.g. two_buckets_per_shelf, harvest_receiving_gap_too_large, stale_receiving_date) and origin/dates/limits.

Bucket Requests (trolley transfer) — /bucket-requests

  • On entry fetchAllocatedBuckets(farm) loads the pick list (grouped by OPL) + the vehicle list.
  • Scan a trolley QR (becomes active) → scan bucket QRs onto it (matched case-insensitively against the pick list); duplicates rejected.
  • "Save N trolleys" → saveTrolleyData per trolley, then getSavedTrolleys refreshes the Saved tab.
  • "Load to truck" → loadTrolleyInTruck({trolley_id, truck_id}) marks the trolley in-transit.

Pending Reshelving — /pending-reshelving · role: Harvest Details Updater

  • listPendingReshelving lists bunches awaiting a matching shelved bucket.
  • Expanding a bunch → listBunchDestinations (matching shelved buckets); pick one → moveBunch.

Workflow · Quality Control

Intake QC — /intake-qc

  • On mount: fetchQcParameters (+ getGreenhouseData if the station has a greenhouse).
  • Scan a bucket → getBatchByBucket resolves the batch (sibling buckets, stems, quarantine state).
  • If quarantine is active → Quarantine Review (releaseFromQuarantine looped per bucket). Otherwise the Inspection form: per-variety sampling, solution readings (level, hygiene, chlorine ppm, pH), quality concerns with auto tolerance %, decision Accept/Quarantine/Reject → submitBatchQuality.
  • A tolerance breach forces Quarantine (Accept disabled).
Note coldroom-qc and packhouse-qc tabs are placeholders ("coming soon"); the QC store has Field/Coldroom/Packhouse control points but only Intake is routed. submitFieldRejects and Field mode are wired but not yet surfaced by a screen.

Workflow · Coldroom logs

Three independent daily logs, all gated by tenant/station and backed by farm + cold-store pickers (loaded via frappe.client.get_list).

  • Temperature Log (/temperature-log) → submitColdStoreTemperatureLog: seven time-slot °C readings (8am–8pm); blanks omitted.
  • Cleaning Record (/cleaning-record) → submitColdroomCleaning: mode, detergent/disinfectant (rate + unit + volume), equipment, sign-off.
  • Inspection Log (/inspection-log) → submitColdroomInspection: multi-select condition flags across 8 areas (floor, roof, walls, lights, doors, shelves, drainage, evaporators); only non-empty areas sent.

Workflow · Corrections & ops

  • Solution Mixing (/solution-mixing): fetchMixingTanks + fetchColdPostHarvestChemicals feed the form; photos upload first (upload_file), then submitSolutionMix.
  • Discards (/discards): scan → createDiscardEntry; typed failure reasons (e.g. bucket_too_young = soft warning).
  • Replacement (/replacement, role-gated): getTraceability → listBucketOpls + listReplacementCandidates; whole-bucket replaceBucket, partial replaceStems, or bunch moveBunch → replaceBunchInOpl.
  • Edit Details (/edit-details, role-gated): getTraceability → correctDetails (variety/stem-length at bucket or bunch granularity), validated against listVarieties/listStemLengths.
  • Traceability (/traceability, read-only): getTraceability renders the Harvest→Grading→Receiving→Shelving→Allocation→Issued timeline with mismatch warnings.
  • Configure Station (/configure-station): generic /api/resource/Farm + /api/resource/Warehouse; persists {userFarm, userGreenhouse} locally (RequireStation gates feature routes).

DocType reference

The Frappe DocTypes these workflows read and write. Field lists focus on the custom fields that drive the app; italic notes mark inferred/secondary types.

Order Pick List (submittable · "OPL")

The order being picked/packed. Header: customer, sales_order, custom_order_name, custom_team (Team A–D/Eldama/Bravo), custom_total_stems, custom_status (Partially Allocated / Ready to Pack), custom_schedule_number (queue position), custom_issued, custom_farm, custom_item_group, date_created. Child table locations = Pick List Item.

Pick List Item (child of OPL · locations)

One line/bucket on the order, carrying the whole transfer→pack lifecycle as check fields: custom_awaiting_transfer → custom_loaded_in_trolley → custom_in_transit → custom_shelved → custom_ready_for_packing → custom_issued. Plus custom_line (Link → Line), custom_stem_length, custom_shelf, custom_bucket, custom_box_id, custom_trolley_id, custom_truck/custom_transit_truck, custom_available_stems_of_exact_length, custom_packrate.

Bucket QR Code

The physical bucket identity. id (PK), status (Available / In Use), last_stock_entry. Auto-created by the harvest flow if missing. DB collation is case-insensitive — bucket ids fold case.

Stock Entry (+ custom fields)

The movement ledger, specialized by stock_entry_type: Harvesting, Receiving, Grading, Shelving. Custom fields: custom_bucket_id, custom_received_bucket_id, custom_bunch_id, custom_harvest_batch_no, custom_scanned, custom_scanned_packing, custom_issued_to (line), custom_opl_scanned, custom_stem_length, custom_greenhouse, custom_harvester, custom_farm.

Farm Pack List → Dispatch Form Item (pack_list_item)

Packing output per OPL+SO+farm. Rows (Dispatch Form Item) are box-aware: box_id, bunch_uom, bunch_qty, custom_number_of_stems, stem_length, custom_opl_id (Link → OPL), custom_line, source_warehouse.

Shelf & Shelf Item

Shelf: shelf_id. Shelf Item (child): bucket_id — a bucket physically on a shelf. The issue/discard flows delete the Shelf Item row to remove a bucket from its shelf.

Other types

  • Batch — groups buckets harvested together; the unit of intake QC.
  • Quality Parameter — concern names + tolerance_thresholds (%) for intake QC.
  • Cold Post Harvest Chemicals — curated chemical list (item_name, stock_uom) for solution mixing.
  • Production Settings (Single) — includes custom_takt_time (minutes) for the packhouse scheduler.
  • Cold Store Temperature Log / Coldroom Cleaning Record / Coldroom Inspection — the three coldroom log doctypes (with condition multiselect child tables on inspection).
  • Solution Mixing — header + chemical child table; Trolley, Vehicle, Line, Stem Length, Bucket Allocation Summary (BAS) — referenced for allocation/available qty.
  • Item / Warehouse / Farm / Greenhouse — masters (varieties via item_group Spray Roses / Standard Roses).
